## ✅ เคาะวันนี้
- **คีย์หลักของตารางตัวต่อ → ใช้ เนื้อหา + ตำแหน่ง ทั้ง 3 ตาราง** (ไฟล์ส่งต่อ 9.4 ข้อ 15)
  - เดิม: คำในประโยค ใช้ ประโยค + คำ + ตำแหน่ง ตามฐานจริง (บ.265) แต่ คำในคู่ถาม-ตอบ กับ คำในบรรทัดบทสนทนา ไม่ได้ใส่คำในคีย์หลัก
  - เหตุผล: คีย์หลักบอกกติกา "1 ตำแหน่ง มี 1 คำ" ตรง ๆ ในผัง ไม่ต้องพึ่งกฎกันซ้ำที่ซ่อนอยู่ในฐานจริง (บ.266) · 3 ตารางเขียนแบบเดียวกัน · เก็บข้อมูลได้เหมือนเดิม
  - แก้ผังแล้ว: แถว "คำ" ของตารางคำในประโยค เปลี่ยนจากตัวหนาเป็นตัวเอียง ในหน้า ER และหน้า 2 (แก้ 2 จุดเท่านั้น เส้นไม่เปลี่ยน)
  - ใส่ในไฟล์ส่งต่อแล้ว: 9.2 ตาราง 6 · 9.4 ข้อ 15 · 9.5
- **กลุ่ม ง พื้นฐานเสียง: 3 จุดสังเกต → ไม่ต้องแก้ ER**
  1. ด่านกับคู่เสียงใกล้ไม่มีเส้นเชื่อม → ไม่ต้องมี เพราะด่านมี 5 ด่านตายตัว และมีด่านเดียวที่ใช้คู่เสียง คือเกมแยกเสียง (`ARCHITECTURE.md` บ.202) คู่เสียงทั้งคลังจึงเป็นของด่านนั้นอยู่แล้ว
  2. กติกาที่อิง 120/200 → เลิกอิงตัวเลขนี้ในไฟล์ส่งต่อ 9.7: ความพร้อมสอบเทียบกับช่องคะแนนผ่านและคะแนนเต็มในตารางระดับ (ถ้าเกณฑ์ระบบ 3.0 เปลี่ยน แก้แค่ข้อมูล) · 60% ข้ามพื้นฐานเสียง เป็นค่าเริ่มต้นของเราเอง ปรับได้ · ดู [[HSK-3.0-ข้อเท็จจริง]]
  3. โน้ตเก่าใน 9.2 ตาราง 12 ที่เขียนว่าประตูนุ่ม "ยังไม่เคาะ" → แก้เป็นเคาะแล้ว 3 รอบ

## ⏳ ยังค้าง
- **ต้องแจ้งบอล:** ฐานจริงต้องเปลี่ยนคีย์หลักของตารางคำในประโยค (ไฟล์ส่งต่อ 9.5) — แก้ด้วยไฟล์ตารางไฟล์ใหม่เท่านั้น
- **แจ้งบอลด้วย (งานโค้ด ไม่ใช่ ER):** หน้าเกมแยกเสียงตอนนี้จับคู่เสียงสดจากรายการคำ (`apps/web/src/app/(app)/practice/ear/page.tsx` บ.96) ไม่ได้อ่านจากตารางคู่เสียงใกล้ — ตรงกับที่อาจารย์รอบ 8 ค้านเรื่อง "ปั้นสด"
- ถามอาจารย์: ระหว่างรอประกาศระบบ 3.0 การสอบจำลองจะใช้เกณฑ์ผ่านอะไร
- **จุดสังเกตจากการไล่กลุ่ม จ–ซ ที่ทีมยังไม่ได้คุย** (ยังไม่แก้อะไร):
  - กลุ่ม จ: เฉลยของข้อเรียงประโยคกับข้อจับคู่เก็บที่ไหน — ตอนนี้เหลือแค่ช่อง "ถูกไหม" ในตัวเลือก · ร่างตอนต้นของไฟล์ส่งต่อเคยมี "ตำแหน่งที่ถูก" (บ.246) แต่ไม่อยู่ในตาราง 16 และไม่อยู่ในรายการที่ตัด (9.3)
  - กลุ่ม จ: เส้นที่ชี้ด้วยคีย์ 2 ช่องแต่ลากจากแถวเดียว (ตัวเลือกของข้อ → คำตอบรายข้อ · บรรทัดบทสนทนา → คำในบรรทัด) — เรื่องวิธีวาด
  - กลุ่ม ฉ: ผู้ใช้ในคำตอบรายข้อกับในรอบการทำ ไม่มีกฎบังคับว่าต้องเป็นคนเดียวกัน — เรื่องกฎในฐานจริง
  - กลุ่ม ช: ไม่มีตารางคนกับบทสนทนา · คนกับคู่ถาม-ตอบ — ขึ้นกับว่าหน้าเว็บต้องโชว์ไหม
  - กลุ่ม ซ: โน้ตเก่าในไฟล์ส่งต่อ 9.2 ตาราง 31 ยังเขียนว่า "รอเคาะ" ทั้งที่ทีมเคาะข้อ 8 แล้วว่าเก็บประวัติ
- เรื่องค้างจาก [[2026-11-18]]: ถามอาจารย์เรื่องหลังบ้าน · หน้าเว็บรู้ได้ยังไงว่าใช้ชุดข้อสอบชุดไหน · ยังไม่ส่งขึ้นกิต

# ส่วนของบอล (19 พ.ย.)

## 🏷️ ปรับป้ายช่องในผัง 32 ตาราง ให้ชื่อช่องที่ชี้ไปตารางอื่นตรงกับคีย์ปลายทาง
- ที่มา: ซ้อมอธิบายตามนิสัยอาจารย์ (รอบ 6 แกเคยงง "user นั้นคือ user นี้ใช่ไหม") บอลสะดุดช่อง "ของใคร" ในตารางรอบการทำ แล้วสั่งตรวจทั้งผัง
- ตรวจด้วยสคริปต์: ช่องตัวเอียง (ชี้ไปตารางอื่น) ที่ไม่ขึ้นต้นด้วย "รหัส" 43 ช่อง + ช่องคีย์หลักร่วมที่เป็นคีย์นอกด้วย ~25 ช่อง + คีย์หลักชื่อชนกัน ("รหัส" เฉย ๆ 4 ตาราง · "รหัสรอบ" 2 ตาราง · "รหัสคู่" 2 ตาราง)
- แก้ 149 ช่องใน 7 หน้า (ผังอีอาร์ + หน้า 1–6) ด้วยสคริปต์ ไม่แตะเส้น/ตำแหน่ง: ของใคร → รหัสผู้ใช้ · หมวด → รหัสหมวด · คำ → รหัสคำ · ข้อ → รหัสข้อ · ชุด → รหัสชุด · ทักษะ → รหัสทักษะ · รหัส (ทักษะ/พิมพ์เขียว/คำตอบ/จุดผิด) → รหัสทักษะ / รหัสพิมพ์เขียว / รหัสคำตอบ / รหัสจุดผิด · รหัสรอบ (ฝึกโมเดล) → รหัสรอบฝึกโมเดล · รหัสคู่ → รหัสคู่ถาม-ตอบ / รหัสคู่เสียง · คีย์หลักที่ชี้ไปตารางอื่นด้วย = หนา+เอียง (เพิ่มในคำอธิบายสัญลักษณ์ทุกหน้า)
- ยังไม่ได้แก้ชื่อช่องในไฟล์ส่งต่อ 9.2 ให้ตรง (ป้ายไทยในตารางนั้นยังเป็นแบบเดิม) — ชื่อคอลัมน์อังกฤษไม่เปลี่ยน

## ✅ มติจากการซ้อม (บอลเคาะ 19 พ.ย. — ไป 0007 / แจ้งตะวัน)
- **role เหลือ 2 ค่า** learner / admin · admin = ทีมทั้งคู่ กดอนุมัติได้ (approved_by จดว่าใคร) · ตัด role approver และตาราง approval_transfers · สถานะเนื้อหา draft → pending → approved ยังอยู่ (ผัง 32 ตารางของตะวันตัดเรื่องตรวจออกหมด — ต้องใส่กลับ: status · approved_by · role)
- **หลังบ้าน = หน้า /admin 3 จอ** (คลังเนื้อหา+อนุมัติ · ชุดข้อสอบ+ประกอบ+ล็อก · เปิดใช้ชุด active + ผลรวม) เจนด้วย react-admin + ra-supabase ทำท้ายสุด — ต่างจากที่ตะวันเคาะ (หน้า Supabase + สคริปต์) ต้องคุยกัน
- **cohort:** not null default 'public' · เข้าทดลอง = 'trial' (แอดมินติ๊ก) · ตัด trial_started_at (วันเริ่ม = วันทำ pre เสร็จ) · ไม่มีค่า team (ดูจาก role)
- ข้อสอบ: ระบบปั้นจากคำที่อนุมัติแล้ว + ตัวลวง 3 คำหมวดเดียวกัน → เก็บเป็นแถว items/item_choices เป็นชุด → หน้าเว็บดึงด้วยรหัสชุด/รหัสข้อ (ไม่ static ตามนิยามอาจารย์ "random ตอนสร้างได้ แต่ต้องอยู่ใน DB ก่อน")
- แพทเทิร์นที่เช็กกับแพลตฟอร์มจริง (Duolingo Incubator ปิด 2021 · Moodle Draft/Ready + version · Open edX Studio/LMS · WordPress roles + Pending Review): users ตารางเดียวแยก role · เนื้อหามีสถานะ+เวอร์ชัน · หลังบ้านแยกจากหน้าผู้เรียน · หน้าแอดมินเจนจากตาราง
- **ตัดช่องซ้ำออกจากผัง (บอลเคาะระหว่างซ้อม):** รอบการทำ ตัด จำนวนข้อ (นับจากคำตอบรายข้อได้) + คะแนนรวม (= ฟัง + อ่าน) · ผู้ใช้ ตัด เริ่มช่วงทดลองเมื่อ (วันเริ่ม = วันทำ pre เสร็จ) → แก้ในผังทุกหน้าแล้ว (ลบ 6 แถว เลื่อนแถวที่เหลือ ย่อกล่อง) · 0007: drop sessions.total · sessions.score_total · users.trial_started_at · ตรงคำอาจารย์รอบ 6 "ไม่ต้องเก็บซ้ำได้ป่ะ"
