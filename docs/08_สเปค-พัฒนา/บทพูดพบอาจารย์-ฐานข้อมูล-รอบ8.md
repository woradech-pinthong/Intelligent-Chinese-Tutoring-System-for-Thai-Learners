# บทพูดพบอาจารย์รอบ 8 — ไล่ฐานข้อมูลตามรูปอาจารย์ด้วยตารางจริง

> รวบจากที่บอลซ้อมอธิบายเอง 16 ต.ค. 2569 (ขัดเกลาคำให้ตรงตารางจริง) · ใช้คู่กับ [[ผังหมวด1-ตามรูปอาจารย์]] (พิมพ์กระดาษ) + Supabase Table Editor + เว็บจริง
> ทุกป้ายทำ 3 จังหวะ: **จอเว็บ** (มิ้นท์กดอะไร) → **รูป** (เกิดแถวที่ตารางไหน โยงด้วยช่องไหน) → **Supabase** (ชี้แถวจริงของมิ้นท์)

---

## ประโยคเปิด

"ผมขอไล่ตามรูปที่อาจารย์วาดครับ แต่เปลี่ยนทุกกล่องเป็นตารางจริงของเรา ผมสมมุติผู้เรียน 1 คนชื่อมิ้นท์ แล้วเดินตั้งแต่เลือกหมวดจนถึงนับคะแนน ทุกจังหวะผมจะชี้ว่าเกิดแถวที่ตารางไหน แล้วเปิด Supabase ให้ดูแถวจริง

สถานะจริงวันนี้ขอบอกก่อนครั้งเดียวครับ: ฐานข้อมูล 24 ตารางสร้างบน Supabase แล้วด้วย migration แต่ระบบล็อกอินกับการส่งคำตอบขึ้นฐานข้อมูลยังไม่ต่อ แอปยังเก็บคำตอบไว้ในเครื่อง แถวของมิ้นท์ที่จะเห็นเป็นข้อมูลสาธิตที่ผมใส่ไว้ให้เห็นรูปร่าง"

---

## 0 มิ้นท์สมัคร → users

"มิ้นท์สมัครใช้งาน เกิด 1 แถวในตาราง users นี่คือ U ของอาจารย์ รหัสของมิ้นท์ในแถวนี้จะถูกยืมไปใช้ทุกตารางที่เป็นข้อมูลรายคน ในช่อง user_id"

## ① หน้าเลือกหมวด → categories + category_progress

จอ: เปิดหน้าเลือกหมวด (5 หมวด มีหลอดใต้ชื่อ)

"นี่คือหน้าเลือกหมวดครับ 5 หมวดนี้ตรงกับ cat 1–5 ที่อาจารย์วาด อยู่ตาราง categories มี 5 แถว ช่องหลักคือ id กับ name_th และ word_count ที่บอกว่าหมวดนั้นมีกี่คำ ตารางนี้เป็นเนื้อหา ทุกคนเห็นเหมือนกัน ไม่เกี่ยวกับผู้เรียนคนไหน

ส่วนหลอดใต้ชื่อหมวดเป็นของรายคน อยู่อีกตารางชื่อ category_progress คือ คน × หมวด เก็บว่าคนนี้เรียนหมวดนี้ไปกี่คำ หลอดเป็น 2 ตารางหารกัน: words_learned ของ category_progress หารด้วย word_count ของ categories (เช่น 22 จาก 70)"

ถ้าถาม "จอบอก 22 แต่ตารางมิ้นท์บอก 1": "จอวันนี้ยังนับจากข้อมูลในเครื่องผม เพราะยังไม่มีล็อกอิน แถวในตารางเป็นข้อมูลสาธิตของมิ้นท์ครับ"

Supabase: categories (แถว id 1 ทักทาย & คนรอบตัว · word_count 70) → category_progress (แถวมิ้นท์ หมวด 1 · words_learned 1 · quiz_best_score 2)

## ② หน้าหมวด 1 → ทักษะ 2 ชั้น

จอ: กดเข้าหมวด 1 เห็นการ์ด ฝึกฟัง ฝึกอ่าน ฝึกเขียน ฝึกพูด

"การ์ด 4 ใบคือ 4 ด้านตามที่อาจารย์วาง ทักษะมี 2 ชั้นครับ

ชั้นบน 4 ด้าน ฟัง อ่าน เขียน พูด ไม่ใช่ตาราง เป็นค่าในช่องของข้อสอบกับคำตอบ (items.module, attempts.generator) เพราะมีแค่ 4 ค่าที่ไม่เปลี่ยน และไม่มีข้อมูลของตัวเองให้เก็บ ส่วนการ์ดบนหน้าจอเป็นเมนูที่เขียนไว้ในโค้ด

ชั้นล่างคือตาราง skills 23 แถว เป็นหน่วยความรู้ที่ละเอียดกว่า ให้โมเดลวัดว่าผิดตรงจุดไหน มี 3 ชนิด: จุดผิดคนไทย 15 ตัว เช่น เสียง 2 เพี้ยนเป็นเสียง 3 · คำศัพท์รายหมวด 5 ตัว · ทักษะหยาบ 3 ตัว คือ ฟัง อ่าน เรียงประโยค ซึ่ง 3 ตัวนี้คือจุดที่ชั้นของอาจารย์มาเจอชั้นของเรา

ข้อสอบแต่ละข้อถูกแปะป้ายในตาราง item_skills ว่าวัดหน่วยไหนบ้าง ข้อหนึ่งแปะได้หลายป้าย เช่น ข้อฟัง 谢谢 แปะทั้ง 21 ทักษะฟัง และ 16 คำศัพท์หมวด 1 ตอบผิดระบบจะนับเข้าทั้งสองหน่วย แล้วค่อยแยกทีหลังว่าอ่อนที่ฟังหรืออ่อนที่คำ"

Supabase: skills (23 แถว ดู code / name_th / type) → item_skills (6 แถว = 3 ข้อ × 2 ป้าย)

## ③ บัตรคำ / ฝึกฟัง → words

จอ: กดเรียนคำศัพท์ หรือฝึกฟัง → ฟังคำ

"เนื้อหาระดับคำทั้งหมดอยู่ตาราง words ตารางเดียว 300 คำ มีครบทั้งตัวจีน พินอิน คำแปลไทย เสียง และหมวด (type ที่อาจารย์วาดคือช่อง category ของเรา) ทักษะต่างกันที่ใช้ช่องไหน: ฟังใช้ช่องเสียงอย่างเดียว ซ่อนตัวจีนกับพินอินจนกว่าจะตอบ อ่านใช้ตัวจีนกับพินอิน ไม่มีเสียง ส่วนเขียนเป็นระดับประโยค อยู่อีกตาราง sentences

แบบฝึกไม่ได้ดึงข้อสอบจาก items ครับ โค้ดเว็บโหลดคำมาครั้งเดียว กรองให้เหลือคำของหมวดที่ผู้เรียนเปิดบัตรแล้ว แล้วปั้นข้อสดในเครื่องผู้เรียน: สับคำทั้งกองครั้งเดียวแล้วหยิบ 10 คำแรกเป็นโจทย์ จึงไม่ซ้ำ ตัวลวง 3 ตัวหยิบจากหมวดเดียวกัน ข้ามคำที่แปลซ้ำหรือเสียงซ้ำ ฐานข้อมูลจึงถูกอ่านครั้งเดียวต่อการเข้าฝึก ไม่ว่าคนจะมากแค่ไหน

เวลาตอบ โค้ดของแบบฝึกเป็นคนติดป้ายทักษะ เช่น ฝึกฟังติดป้าย SKILL-LISTEN แล้วจดลง attempts เหมือนข้อสอบ แต่ชี้ไปที่คำ (word_id) แทนข้อ (item_id)"

ถ้าถาม "ทำไมไม่ให้ฐานข้อมูลสุ่ม": "ให้เบราว์เซอร์ทำถูกกว่าครับ ไม่ต้องยิงถามเซิร์ฟเวอร์ทุกข้อ และฝึกต่อได้แม้เน็ตหลุด ส่วนข้อที่ต้องตายตัว เช่น ควิซ pre/post ค่อยดึงจาก items"

ถ้าถามเรื่องประโยค/บทสนทนา: "ระดับประโยคอยู่ตาราง sentences ประโยคหั่นเป็นคำไว้ในช่อง tokens และโยงกลับไป words ทีละคำด้วย sentence_words ส่วนอะไรที่เป็นข้อสอบมีโจทย์+ตัวเลือก+เฉลยผูกกัน เช่น บทสนทนา อยู่ items ตอนนี้ sentences ยังว่าง ประโยคร่างรอตะวันตรวจแล้วค่อยใส่"

Supabase: words (กรอง category = 1 → 70 แถว · ดู hanzi / pinyin / meaning_th / audio_path)

## ④ ควิซท้ายหมวด → items → sessions → attempts

จอ: กดควิซท้ายหมวด → กดเริ่ม → ตอบ 1–2 ข้อ

"ควิซดึงข้อจากตาราง items ครับ นี่คือตาราง Lis ที่อาจารย์วาด 1 แถว = 1 ข้อ: V1 คือ audio_path เสียงของข้อ · Ans คือ answer_key เฉลยตัวล็อก · A1–A4 คือ choices ตัวเลือก 4 ตัว · module บอกว่าเป็นข้อฟัง · item_type บอกรูปแบบการตอบ เช่น ปรนัย เลือกรูป จริง/เท็จ

ข้อสอบเจนมาจากคำ: เอาเสียงของคำเป็นโจทย์ เอาคำแปลของคำอื่นในหมวดเดียวกันเป็นตัวลวง ไม่ซ้ำ แล้วเก็บไว้ใน items ให้ทุกคนได้ข้อเดียวกัน ตั้งใจไม่ผูก items กับ words ด้วย id เพราะข้อสอบต้องตายตัว แก้คำทีหลังข้อต้องไม่เปลี่ยน จดที่มาไว้ในโน้ตของข้อแทน

ข้อที่ AI หรือทีมสร้างเริ่มที่ draft ต้องให้ตะวันซึ่งเป็น approver อนุมัติเป็น approved ถึงจะถูกเสิร์ฟ DB บังคับให้เอง

พอมิ้นท์กดเริ่ม เกิด 1 แถวใน sessions ว่าใคร ทำรอบชนิดควิซ หมวด 1 เริ่มเมื่อไหร่ ยังไม่มีคะแนน นี่คือ C ของอาจารย์ ตอบทีละข้อ แต่ละข้อลง attempts 1 แถวทันที ชี้ว่ารอบไหน (session_id) ใครตอบ (user_id) ข้อไหน (item_id) ตอบอะไร ถูกหรือผิด (is_correct 1/0) และวัดหน่วยไหน (skill_id ที่ก๊อปมาจาก item_skills) พอทำครบ sessions ถึงถูกเติมว่าทำ 3 ข้อ ถูก 2 ข้อ

ตารางผลที่อาจารย์วาด U · C · Lis · # → 1/0 คือ attempts ครับ คอลัมน์ตรงกันทุกช่อง ไม่ต้องมีตารางผล 4 อันแยกตามทักษะ ใช้ตารางเดียวแยกด้วยช่อง ส่วน sessions เป็นใบสรุปของรอบ อาจารย์เรียกคู่นี้ว่าดิบกับสรุป"

ถ้าถาม "ข้อในจอคือ items แถวไหน": "ตามแบบควิซดึงจาก items ที่ตะวันอนุมัติครับ วันนี้คลังยังว่าง ควิซเลยปั้นจากคำไปก่อน 3 ข้อใน items เป็นตัวอย่างที่ผมใส่ไว้ให้เห็นรูปร่าง"

Supabase: items (3 แถว) → sessions (แถว id 2 quiz · หมวด 1 · score 2 / total 3) → attempts (3 แถวของรอบ 2: is_correct true, true, false)

## ⑤ นับยังไง

"อยากรู้ว่ามิ้นท์ได้เท่าไหร่ เปิด attempts กรองเอาเฉพาะแถวที่ user_id เป็นมิ้นท์และ session_id เป็นรอบ 2 ได้ 3 แถว ดูช่อง is_correct เป็น 1, 1, 0 นับที่เป็น 1 ได้ 2 จาก 3 ตารางเดียว เปลี่ยนแค่ตัวกรอง: อยากรู้รายทักษะกรอง skill_id อยากรู้รายหมวดกรองผ่าน sessions.category

ที่เพิ่มจากรูปอาจารย์คือทุกคำตอบติด skill_id โมเดล BKT เอาไปนับถูก/ผิดแยกตามหน่วย แล้วปรับความน่าจะเป็นทีละคำตอบ ได้ความแม่นรายหน่วย เก็บที่ mastery_snapshots ตอนนี้ยังว่าง รอคำตอบจริงจากการทดลอง"

## สิ่งที่จะถามอาจารย์

1. ข้อสอบ pre/post ใช้ 40 ข้อเต็มตามโครง HSK 1 (ฟัง 20 + อ่าน 20) หรือฉบับย่อ
2. ข้อความขอความยินยอม: ถอนความยินยอมแล้วลบข้อมูลระบุตัวตน แต่เก็บประวัติการตอบแบบไม่ระบุตัว — โอเคไหม
3. ช่วยแนะนำครูสอนจีน/ผู้ทดลอง 5–10 คน
4. (ถ้าแกติดใจ) จะเพิ่มช่อง items.word_id สำหรับข้อที่มาจากคำเดียวไหม — เพิ่มได้ด้วย migration ถัดไป

## กติกาตอนพูด

- แกถาม "งงมั้ย" → ถ้างงบอกจุดที่งงจริง ไม่ตอบ "ไม่ครับ" แบบรีเฟล็กซ์
- แกชี้นำไม่ตรงของเรา (เช่น "ต้องมีตารางผล 4 อัน") → "ของเราต่างนิดหนึ่งครับ ใช้ attempts ตารางเดียว แยกด้วยช่อง skill_id"
- อะไรที่ "เก็บ" อยู่ในฐานข้อมูล · อะไรที่ "สุ่ม ตรวจ คำนวณ" โค้ดเว็บทำตอนเปิดหน้า — ตอบให้ชัดว่าอยู่ฝั่งไหน
- สถานะจริงพูดครั้งเดียวตอนเปิด ไม่ต้องแก้ตัวซ้ำทุกป้าย
